# MCP OAuth for ChatGPT and Claude

## Scope

Let an external MCP client connect to `/api/mcp`, sign in with the existing
Resume account, approve access, and use the existing eight tools. Read and
draft editing are selected by default (owner decision, 7 November 2026).
Accepting drafts remains an owner-only action in the Writing Desk.

## Implementation

1. Use `@better-auth/oauth-provider` matching Better Auth 1.6.11, plus its JWT
   plugin. Enable authorization-code + rotating refresh grants, S256 PKCE and
   dynamic registration, with `mcp:read`, `mcp:write`, and `offline_access`.
   Use DCR in both clients; CIMD requires a future provider upgrade.
2. Add the provider's Prisma tables and signing keys through a migration.
   Expose RFC 8414 authorization-server and RFC 9728 resource discovery.
3. Keep `rsm_` authentication; additionally verify OAuth signatures, issuer,
   MCP resource audience, expiry, client state, and current user consent.
   Resolve the profile from the verified subject. Never accept a profile id
   from the client. Keep OAuth actor identity in the existing draft event log.
4. Reuse normal account sign-in through a local OAuth resume callback, then
   show consent in the existing auth layout. Verify the signed request through
   the provider before displaying client information and requested scopes.
5. Add connected-app listing and revocation to API-token settings. Revocation
   removes consent and refresh/access tokens; the MCP verifier checks consent
   on every request so issued JWTs immediately stop working.
6. Expose scoped API-token creation and expiry for CLI/static-header clients.
   Document ChatGPT and Claude setup and deployment requirements.
